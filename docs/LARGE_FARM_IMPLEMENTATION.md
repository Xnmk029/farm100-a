# G5 大农场与实时生产（开发中）

2026-09-10。0.5.3-alpha.1，模拟规则仍为 garden-v0.5.0；上一个已验收检查点为 a2598b9 / 0.5.2。完整产品目标保持进行中。

## 当前实现

新农场可选择 8、16 或 32 的尺寸上限。选择只影响下一次新建，不改变已有存档；新档都从 4×4 开始，研究并支付原有材料后，按 4→6→8→16→32 扩地。旧档保持原尺寸与规则。

自由农场增加“执行时实时观看 · 1×”。开启后，已验证、已落盘的批次驱动实际画面，宿主按每秒 24 模拟 tick 确认后续批次。取消、子进程退出和超时会释放观看节奏的等待；它不改变模拟动作、成本或冲突次序。关闭选项时保持快速执行，完成后可独立回放。

实时观看最多保留 192 条事件及一个世界前态；完整事件仍在磁盘。已结束的当前运行可使用本次校验过的封存描述符立即回放，避免结束时再做整段重复校验。重新打开历史仍逐事件重验，分页读取仍检查片段哈希。

16×16 和 32×32 新日志使用无损 gzip 片段，保留原始事件、哈希链与规则验证。旧 JSON 片段继续支持。片段解压后最多 16 MiB，存储片段总量仍最多 1 GiB，事件与片段数量上限不变。压缩 `.farmjournal` 使用 export-v2 的逐行 gzip/base64 片段；旧 export-v1 可继续导入。导入限制解压体积、编码及总存储配额，失败临时目录不发布到历史。

## 真实成长与生产程序

- `examples/garden-large-progress.js`：从零生产，获得 23 项研究，逐级扩到 32×32，并准备启动材料。缺水时自然生长，不在播种过程中消耗已预留的种子粮食。
- `examples/garden-mixed-production.js`：八台机各负责四行，覆盖八种作物、轮种、共生、合生采收、维修与补水；共享加工台采用原子锁，材料不足时回到基础粮食生产。
- `scripts/large-farm-prepare.ts`：通过真实 VM、逐批规则校验及日志生成存档，再重开检查完整世界。没有注入库存或解锁。

成功准备记录：`artifacts/large-farm/preparation-v2/`。实际 20,065 条事件，操作成本 136,402，开放 32×32，研究 23 项；生成的 `earned.garden.json` 可通过客户端打开。第一版资源预留失败证据保留在 `preparation/`。

## 已有检查与测量边界

类型检查、构建和 50 项源码测试通过；经营、挑战、多机开发版界面回归通过。测试新增实时窗口释放与绝对时间、大农场压缩读写、封存描述符、片段变更拒绝和解压上限。

校准条件：i5-12450H、RTX 3060 Ti、约 16 GiB RAM；完整硬件、驱动及软件信息以每次 performance-metadata.json 为准。

- `calibration-30/`：p95 16.8 ms，中止到结果约 574 ms，重开一致；窗口中途从 1080p 改为 4K，不计为固定分辨率验收，时长和作物覆盖也不足。
- `calibration-180/`：八种作物及共享争用均出现，180 秒约 115 MB 原始片段；中止到结果约 113 ms，重开一致。窗口尺寸正确，但帧序列出现持续约 1 Hz，符合遮挡降频特征；帧时间 p95 超出 200 ms 直方图上限，报告 200.1 是溢出桶而非精确 p95。该次性能不通过。

最终测试窗口固定为 1920×1080、DPR=1，放在屏幕角落并保持置顶，记录窗口和文档可见状态。使用真正的持续生产，既不是等待循环，也不是离线帧导出。每五秒记录帧数、动作、种植、竞争、缓冲、记录体积和各进程内存；保存完整帧间隔直方图与硬件信息。
