# FARM100 评分 v2 · 0.5.4-alpha.1

本版新增独立模型评分工作台、版本化测试清单、真实调用器、预算账本、人工评分和可携带证据导出。保留原挑战评分 v1 与 Luna 单种子历史数据；它们不进入 v2 正式榜单。

## 使用预览包

启动 `release/scoring-v2-0.5.4-r2/win-unpacked/FARM100.exe`（保留整个目录），或安装同目录的 `FARM100 Setup 0.5.4-alpha.1.exe`。点击右下角“评分工作台 v2”，导入 `artifacts/scoring-v2/bundle.json`。预览 ZIP 解压后导入 `evidence/bundle.json`，必须保留其 references、runs、calls 子目录。

工作台提供首次/修订视图、逐题分项、真实事件、调用元数据、人工评分表与修改记录。JSON 导出会携带参考、运行与调用文件到同名 `.evidence` 文件夹。CSV 包含模型、题目、案例三级行及各评分维度；空白表示缺证/未评，不能当作零分。界面和 CSV 保留两位小数，JSON 保留计算精度。人工评分保存在本机应用数据目录，重新导入同一清单时保留已评且证据相同的提交。

## 评分规则

正确性30：各案例按目标完成比例计分，每个目标先截断至100%，不能靠超额生产补偿别的缺项。异常结束的该例最多15。旧排序按横纵相邻约束满足比例计正确性，完成收获才算通关；课程按各课具体行为检查项等权计算完成比例。操作15：合法调用、无非预期失败、关键操作各5；课程要求的越界探测除外。挑战关键操作从真实完成事件/计数器判定，多机派发不重复计算。

效率15：仅通关案例计 `15 × min(1,参考主指标/实际主指标)`；实际为零时给15，参考零而实际正数给0。保留原始运行时间/成本（事件记录中）、主指标和相对节省比例。所有案例客观分先平均，再加该题人工40分。

人工四项为算法建模与策略、正确性论证、复杂度与取舍、边界与实现一致性。每项只允许0/2.5/5/7.5/10，分别代表缺失或错误、仅概述、基本合理但遗漏、充分且一致、完整准确且有证据。必须填写评审人、理由及 `code:行号`/`case:完整案例ID` 引用；格式错误提交可引用 `response`。空项显示人工待评，无正式总分。修改追加版本，不覆盖旧评审。QA 示例评审只存在独立测试配置；真实 bundle 保存用户授权的主助手AI评审，并明确标注评审身份。

每题独立调用，只提供题目/API/规则与输出格式，不提供基线源码、Luna 或其他模型成绩。首次一次；真实失败后允许一次修订，分别展示。鉴权、限流、缺失运行属于基础设施问题。仅全部93例证据完整且人工完成才允许总榜。

## 执行与恢复

```powershell
pnpm benchmark:v2 --pilot
pnpm benchmark:v2
node node_modules/tsx/dist/cli.mjs scripts/benchmark-v2-report.ts
```

若模型因额度问题暂停，额度实际恢复后可明确执行：

```powershell
pnpm benchmark:v2 --resume-infrastructure --model=gpt-5.3-codex-spark
```

该命令归档旧检查点，只移除该模型没有答案的基础设施失败槽位以重试连接；已生成的首答和修订不重抽，历史调用/费用账本不删除。已有答案但运行不完整的记录需用同一源码补验，不应重新生成答案。进程中断后的未结算预留继续占预算，未知费用不释放。
