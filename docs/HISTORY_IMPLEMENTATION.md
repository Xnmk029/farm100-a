# G5 记录与恢复：第一阶段

2026-09-08，桌面版本 0.5.1-alpha.1。模拟规则继续使用 garden-v0.5.0，本次改变记录和客户端行为，不改写旧挑战成绩。

本文件保留 0.5.1 阶段记录。0.5.2 已进一步接入有界流式执行和分页界面，最新状态见 [流式与分页](STREAM_IMPLEMENTATION.md)。下文“尚未完成”描述的是 0.5.1 当时的边界。

## 已实现的链条

每次从客户端执行程序，先保存程序、固定配置与完整初始世界，再启动隔离运行器。运行器仍按最多 64 个事件传递一批，宿主将批次写入临时文件、flush、原子改名为不可变片段，再保存可替换索引与摘要，最后向运行器确认。写入失败会显示错误、停止确认并终止执行。开始过程中点击中止也会保留中止意图，直到子进程启动。

存储位置为 Electron userData 下的 `farm100/garden-history/<run-id>/`：

- `header.json`：源程序、版本化配置、完整初态、创建时间与校验值。
- `chunks/00000000.json` 等：连续编号、前片段哈希、片段前快照及最多 64 条事件。
- `index.json`：片段对应的事件和时间范围，用于定位跳转；可从片段重建。
- `summary.json`：历史列表用的轻量摘要。正常客户端使用单实例锁，避免两个桌面进程同时操作同一档案。
- `end.json`：正常或受控中止后的结果、尾哈希、事件数与日志。缺失时不能当作完整运行。

历史页支持程序标题、关卡与编号检索，按模式及结束/中断状态筛选，分页展示。打开记录不会运行源程序。旧 `gardens/*.farmgarden` 自动保存记录仍可检索和打开，按原规则验证。

恢复逐个读取连续片段，遇到缺失、截断或哈希错误就停止，保留并提示最后完整前缀；不会跳过坏片段拼接后面的事件。临时文件不计入恢复。随后用对应冻结版本的模拟引擎重新验证动作、状态和调度，再重建索引。校验和不能代替规则验证。

恢复保留田地、库存、研究、队伍位置、共享数据和未完成队列。再次执行从程序首行创建新 VM；暂停在动作中的自由农场需先明确撤销未完成动作。恢复不意味着 JavaScript 调用栈或局部变量继续执行。

## 验证

自动测试覆盖普通农场、8 机维修任务及冻结 0.4 记录的落盘重开，各抽查 100 个索引跳转点；另覆盖陈旧/缺失索引、残留临时文件、损坏片段、记录头篡改、路径越界、旧版记录及查询分页。

实际 Electron utility process 专项包含正常完成、启动即中止、批次后中止、子进程退出和注入 ENOSPC 写入失败。每种情况下，宿主返回的事件前缀与重新打开的磁盘记录一致；磁盘故障后停止新批次确认。

桌面崩溃专项使用独立测试档案：主进程在持久化批次后直接以 86 退出，未写正常结束记录；第二个进程使用同一档案恢复。开发版实测恢复 200 条事件、63 tick，队伍共享数据和成本一致。该测试世界专门赋予协作研究以定位恢复链条，不作为新档成长证明；成长证据仍见多机阶段记录。

发行包的实际退出、恢复、检索及界面证据见 `history-release-verification.json`。

## 尚未完成的 G5 工作

这是持续分段落盘与恢复的交付，**不是无界长期运行架构已完成**。运行器和当前回放界面仍保留完整内存事件数组，原来的单机 10,000 / 多机约 24,000 事件保护上限仍在。索引读取已验证，但界面打开完整记录仍会整体验证和加载。

下一步需将运行端事件缓冲、宿主传输、验证和回放窗口统一为有界分页架构，补齐长时运行的超时与取消语义，再进行 32×32、8 机、30 分钟的实测。声音、完整混合生产录像、干净 Windows 安装与升级，以及固定原版实录和外部评价也仍待完成。整体产品目标保持未完成。
