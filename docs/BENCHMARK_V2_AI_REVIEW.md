# 两模型 v2 补测与 AI 评审

用户已授权由本任务主助手对四项40分进行判分。评审人统一标注“Codex 主评审（AI，用户授权）”，不是独立人类专家评审。沿用冻结的0/2.5/5/7.5/10五档，不按通关率机械换算人工分。

每份首次及失败后一次修订均单独阅读代码和设计说明，对照真实事件。策略项看是否对准题目和资源/状态建模；论证项检查其关于正确性与终止的主张；复杂度项检查实际控制流、移动、缓存和等待成本；边界项检查API约束、资源不足、等待上下界及说明与实现一致性。10分需该维度完整准确且可核验，7.5分表示充分但仍有明确遗漏。不会仅因低于参考效率再次机械扣人工分。

初步评语保存 review-drafts.json，每项引用真实代码行；应用时校验行号、源码哈希并增加案例引用，追加修订序号。worker执行期间仅写 reviewed-preview.json，避免覆盖进行中的测试；结束后再合并 bundle.json。

历史 Luna 单种子成绩不代替新测试。此次新答卷使用相同冻结题面模板、独立临时上下文、Codex CLI正常订阅登录、gpt-5.6-luna/max。Spark保留现有首次和一次修订，只补未完成项。订阅额度与API预算继续分开。

Luna 首道正式请求因调用器180秒等待上限被终止，记录为基础设施错误；随后将原生CLI等待上限统一延长至600秒。被终止调用的请求和账本继续保存，不删除历史证据，不作解题失败。2026年9月11日用户告知 Spark 额度恢复，实际调用成功后继续未完成项，没有消耗重置额度。

Luna首道多机收获最终通过CLI收到完整答案（约461秒），保留为有效首次提交。由于CLI延迟高，尚未收到完整答卷的维修调用取消并保留基础设施记录；其余题目改用独立Luna max子代理，fork_context=false，逐题相同题面，不允许工具或读文件。每次调用记录显式模型覆盖、代理ID、请求、响应及接收时间；子代理通道不暴露后端修订号和逐调用token用量，这些字段保持未知。生成耗时明确为派发至收到完成结果的时间，包含编排延迟。

当前完整源码、首次/修订分项及所有AI评语见 artifacts/scoring-v2/AI-REVIEW-REPORT.md。生成过程的模型与评审者分离：Luna/Spark提交答案，主助手根据原始代码和真实运行证据评分。

Luna 的布局三阶、迷宫二阶修订在隔夜中断时尚未交付答案。恢复原代理、原上下文后，仅要求继续原 JSON 答复，未提供额外算法反馈。调用证据保存续接消息；派发至接收耗时包含隔夜暂停，不能视为纯生成耗时。

更新后的评分导入保留本地已有评审，并追加新答卷的评审历史；重复导入不重复增加记录。安装包验收检查增量导入、已完成总分、未完成项目缺证状态，以及界面、JSON、CSV一致性。

解读限制：本轮相当一部分失分来自API合约和初始状态理解，不能直接当作纯算法难度。冻结提示对 collect 只描述收集 key/relic，没有明确写出无参数签名；实际引擎只接受 collect()。两模型沿用同版题面，修订反馈均为案例状态、完成率、终止类别与检查项。本轮不在中途改提示或重抽首答；下一版应补全API签名、返回值示例和具体错误消息，再独立比较成绩。
